# VideoPocket - 網頁媒體下載與擷取 <img src="extension/icons/48.png" width="32" height="32" alt="VideoPocket icon">

**[下載 ZIP（約 2.2 MB）](https://github.com/g114056175/my_tools/releases/download/video-pocket-v1.0.0/VideoPocket.zip?build=size-binding-29)** · 解壓約 6.9 MB

在 Chrome 的小型視窗中，選擇目前影片並下載影片、音檔或字幕。所有處理都在本機瀏覽器內完成，無須另外安裝程式。

**1.0.0 · Chrome 120 以上。** 目前發布內容以本 README、截圖與隨附 `extension/` 資料夾為準。

開發這個工具，是希望把可取得的影片、音訊與字幕交給 LLM 整理，減少模型因無法讀取網頁連結而不能分析內容的情況。下載後可自行將素材提供給使用中的模型；本工具不會自動上傳素材。

## 介面與功能

最上方顯示目前影片；同頁有多個來源時，可用下拉選單切換。右上角「↻」會清除先前選片紀錄並重新偵測來源；「⌖」固定在它的左側。

選單中有實際名稱的影片排在「影片 1」等自動編號前；排序保留原本的選取與播放器對應。

Reddit 會優先讀取所屬貼文標題；「影片播放器」等通用標籤以自動編號表示。Twitch Clips 與頻道介紹影片分別依所選播放器的 Clip／VOD 識別取得來源。X 可解析貼文提供的 MP4／HLS 版本，引用貼文保留內層影片的對應關係；廣播回放會核對貼文卡片與獨立廣播頁的身分，再讀取 HLS。可用性仍取決於實際播放資料與授權。

品質「最佳」會附上目前格式可用的最高解析度，例如「最佳（1440p）」。畫質偏好高於來源最高可用畫質時，自動降級不會覆寫原偏好；明確改選其他畫質才更新偏好。X 標示的 GIF 若實際提供 MP4，工具保留 MP4 格式，不自動轉成 GIF。

**社群動態牆／多影片頁面**：點右上角「⌖」，將滑鼠移到影片並點選；瀏覽器支援時會自動重開 VideoPocket，否則再次點工具列圖示。藍框會標示選取範圍，Esc 取消，30 秒未選取會自動結束。下拉選單切換目標時會捲到該影片。選取期間會攔下該次影片點擊，避免誤觸播放或跳轉。選擇依分頁、文件與影片識別記住；動態牆換片或播放器被重用時，會要求重新選取。尚未載入的影片需先捲到畫面，無法確認來源時可進入單篇貼文再試。

每次開啟工具視窗或切換影片，會以綠色外框與影片名稱標示目前目標，不影響影片操作。標記隨工具視窗顯示，關閉時立即移除。登入等彈出視窗遮住影片時會隱藏標記。無法取得下載來源時，以頂部簡短紅字提示。標題會依實際欄位寬度省略，不固定 24 字。

選片期間與完成後，工具列上的擴充功能圖示維持原樣，不加上選取或打勾徽章。

更新這版後，請在擴充功能管理頁重新載入，並重新整理原影片頁，才能從播放器建立時觀察來源。取得可用媒體後才顯示「影片／音檔／字幕」操作區；只有影片元素、沒有可讀取的來源時，不顯示停用的下載表單。已有的下載工作不受影響。

### 影片

選擇來源提供的品質並按下載，每次都能指定儲存位置與檔名。記住上次選擇的模式、格式與品質。保留來源編碼，必要時在瀏覽器內合併影音。

影音處理完成後，若原先指定的儲存位置無法寫入，會保留已完成的檔案並改由 Chrome 下載管理員儲存；此時可能再次顯示儲存對話框，不必重新下載或處理影音。

儲存檔名會清除瀏覽器不接受的不可見字元，畫面上的影片標題不變。若瀏覽器仍拒絕檔名，會沿用已完成的檔案，以 `VideoPocket` 加原副檔名再嘗試儲存一次。

已綁定的完整畫質清單優先保留，播放器當下使用的低畫質串流可作失效備援。多版本探測會優先保留不同畫質，避免低畫質 CDN 備援佔滿檢查名額；畫質統一以畫面的短邊標示；MP4 可讀取到實際尺寸時，以檔案資料修正畫質標示。仍無法保證取得網站未暴露的所有版本。

片長及格式可確認時，下載按鈕下方可展開「片段下載」，以同一時間軸的起迄節點或時間欄選取片段。來源支援時間索引時，先取得涵蓋區間的影音資料，再精準裁切；無可靠索引但格式可處理時，可先完整下載後裁切，展開時會顯示黃色提醒。切點與格式適合時直接複製或只重編邊界，其他情況可能重編整個選定區間。無法確認片長或格式不適合時，保留完整下載。

HLS／DASH 會依時間選取所需分段與解碼前置資料；SIDX 與 Y 站 SABR 使用各自的索引／串流流程。一般直連 MP4 可利用完整 sample table 規劃區間，但來源須支援 HTTP Range 並提供可靠索引；僅知道片長不代表能局部下載。HLS 傳輸改以無資料進展判定逾時，精準裁切也修正了小數切點可能產生重複時間戳畫格的問題。

### 音檔

下載獨立音軌，或從影片中抽取音訊。格式由來源決定，例如 M4A、WebM；不強制轉成 MP3。沒有可用音軌時，下載按鈕停用。

### 字幕

選擇字幕來源與輸出格式，按「擷取」後可預覽、複製或下載。格式可直接切換，無須重新擷取：

| 格式 | 用途 |
| --- | --- |
| 純文字 | 移除時間資訊，方便交給 LLM 整理，副檔名為 `.txt` |
| TXT | 每句保留時間標記，方便閱讀與定位 |
| SRT | 含序號及起迄時間，適合一般字幕播放器 |
| VTT | WebVTT 字幕，適合網頁播放器 |

更改副檔名不會轉換字幕結構，請先在工具中選擇輸出格式。字幕來源依使用者語系及英文優先排序；沒有字幕時，字幕分頁停用。

影片與字幕分別偵測；影片來源尚未配對或請求被拒絕時，已取得的字幕仍可擷取。

下載與字幕擷取在收起視窗後仍繼續執行。字幕結果限目前頁面，重開工具視窗可查看，重新整理、導覽或關閉分頁後失效；可在不同分頁分別啟動擷取。同一影片已有下載任務時，影片與音檔下載按鈕暫時鎖定；切換其他影片不受影響。工作列可查看進度、暫停／繼續或取消，合併與儲存階段不提供暫停。

## 適用範圍與限制

本專案僅供個人測試與技術研究使用。請勿違反串流媒體或其他網站的服務條款，並僅處理自己有權存取與保存的內容。使用者應自行確認相關授權與適用法規；本工具不提供繞過 DRM、付費或存取限制的功能。軟體依現況提供，不保證支援所有網站或持續可用；完整授權與免責條款請見 LICENSE。

- 可處理 Y 站、B 站、標準 HTML 影片及部分動畫網頁；陌生網站也會嘗試辨識直連影片與 HLS/DASH 串流、播放器來源、結構化播放資料及可對應的 MSE 載入紀錄。可用性取決於實際來源、登入狀態與網站變動。
- 社群貼文的可用性依該頁實際提供的播放資料而定，不能保證整站所有影片可下載。工具不會把同頁所有影音請求任意套給所選影片；只有能對應到播放器或貼文識別的來源才採用。部分 Worker 播放器、未暴露來源的自訂協定或 SPA 切換仍可能無法辨識，可先開啟單篇貼文並重新整理。
- **Y 站字幕**：擷取前，請在播放器開啟字幕，並選擇與工具相同的來源。例如要擷取「中文（台灣）」，播放器也先選「中文（台灣）」。多個同語言作者版本也需對應。
- **B 站字幕**：依目前 BVID 與分集識別查詢字幕 API，部分字幕由 AI 語音辨識產生。來源尚未載入、登入／權限限制、API 暫時拒絕或字幕檔失效，都可能導致擷取失敗；可稍候再擷取，必要時重新整理影片頁與工具。無法取得站方未提供的字幕。
- 已知大小及可確認對應所選影音組合的全片平均值，統一顯示「約 …」；音軌組合不明或缺少資料時顯示「大小未知」，片段不使用全片平均值推估大小。這不代表無法下載。有可靠 byte range 時按實際取得的 bytes 回報進度，其他來源依片段完成情況估算，下載完成後另有處理／儲存階段。
- 無法處理 N 站等 DRM 保護影片，也不提供 DRM 解密、直播錄製或登入／付費權限繞過。部分網站要求先正常播放、完成分級確認或廣告，才能提供有效來源。
- 沒有另設檔案大小上限，仍受磁碟空間、瀏覽器與格式相容性限制。暫存隨目前瀏覽器會期使用；重開 Chrome 後不保留續傳能力。

### 處理方式

- **Chrome Manifest V3**：popup 提供操作，service worker 管理佇列，offscreen document 與 worker 負責背景下載及處理。
- **來源探索**：從 document_start 在每個可存取的 frame 觀察播放器正常讀取的 Response/XHR 與 MSE appendBuffer，透過物件關聯追溯分段的 HLS/DASH 清單；另讀取影片元素、shadow DOM、播放器來源與有相同媒體 ID 的 JSON 模型。只有有證據屬於同一影片的多畫質才合併；多播放器只採用 player-owned 來源，單播放器仍可用實際時長驗證無綁定候選，但不以時長作影片身分。瀏覽器層亦記錄有數量與時效上限的成功影音請求，限制於同分頁、文件及 frame 配對；Worker 僅讀取 bounded metadata，不保存影片播放緩衝。Y/B 等特殊播放協定仍保留必要的適配。
- **影音處理**：解析 HLS/DASH，辨識容器與音軌，取得原始檔或分段；標準 HLS AES-128 使用正常播放提供的金鑰。分離影音以 stream copy 合併，音訊抽取保留原編碼。
- **暫存與儲存**：資料分段寫入 OPFS，每條影音軌最多預取四個片段，AES-128 限制為兩個。長度已知、未加密且沒有備援路由競速的合適分段可直接寫入輸出位置；其他情況依來源順序組裝並清除片段。合併器讀取磁碟來源，成品以區塊寫入選定檔案，避免將整部影片放進記憶體。完成、取消或一般失敗後清理暫存；非正常關閉留下的孤立影音暫存，於下次開啟工具視窗且沒有活動工作時清理。使用者下載的成品保留。
- **續傳與防重複**：對暫時網路問題有限次重試，支援可用的 HTTP Range／分段接續；同一影片使用穩定識別鎖定任務，不因重新開啟視窗或再次解析來源而重複建立。
- **字幕**：取得站方字幕檔、API 回應或已載入的文字軌，統一成時間與文字片段，再於本機輸出 TXT／SRT／VTT。Y 站保留所選來源，B 站核對目前影片及分集識別。
- **隱私**：不使用下載後端，不自動傳送素材給 LLM，也不自動上傳診斷。來源授權由瀏覽器正常處理；不保存 Cookie 值或完整簽名網址為診斷紀錄。

來源觀察、候選配對、媒體驗證、區間規則及傳輸分別由獨立模組處理；`background.js` 協調工作生命週期，`offscreen.js` 組合解析與下載流程。注入網頁的函式需要自包含，部分入口保留此形式以符合 `chrome.scripting.executeScript` 的序列化要求。

`player-config.js` 補讀可由播放器 ID 核對的既有設定，例如 `flashvars_<id>.mediaDefinitions`；只讀取已知欄位，不執行網頁 script 文字或遍歷全部全域變數。同一播放器中的空白備用元素可與實際播放元素合併；多個活躍元素或識別衝突時保留分開，避免配錯來源。`remote: true` 的媒體查詢 API 不會被當作 MP4 檔案。

`document-media.js` 為沒有影片 ID 的單一 `blob:` 播放器提供有限補救：只從目前文件仍存在的 JSON 媒體資料取得候選，再探測實際影音格式與時長。同一媒體模型中的多畫質驗證通過後可合併；無法證明同屬一部影片的多個候選仍不採用。探測前後會核對同一文件、播放器、blob 與 JSON，防止切換影片後沿用舊資料。此流程不執行任意 script、不從 blob UUID 猜下載網址，也不保證所有自訂播放器皆可辨識。

開發時以 `npm install` 安裝開發依賴，`npm test` 執行測試；修改觀察器來源後執行 `npm run build:observer` 更新隨附 bundle。`work/` 是本機媒體與驗證產物目錄，已從 Git 排除；必要的小型測試樣本保留於 `tests/fixtures/`。

相容性測試使用固定的 Facebook、TikTok、Instagram／Threads、X、Dailymotion、Vimeo 與通用播放器資料，分別走 JSON.parse、Response、XHR、Worker 等適用入口；檢查經篩選、暫存與選片後仍保留身分、來源、格式與時長。測試亦包含隨附觀察器 bundle、無關流量與多影片配對。修改共用欄位或探索流程時須通過這些回歸測試；它們驗證固定資料的程式行為，不代表已實測所有網站的即時登入、CDN 與下載狀態。

需要重建 Mediabunny 時，先執行 `npm ci --prefix evaluation`，再執行 `npm run build:mediabunny`。建置會核對鎖定的 1.61.6 版本、套用 Matroska 影格時長修正並匯出裁切所需介面；不要以未套用修正的通用 bundle 取代。可用 `node evaluation/build.mjs --output work/mediabunny-check.js` 先產生比對檔，詳細說明見 [`evaluation/README.md`](evaluation/README.md)。這些 npm 套件只用於開發建置，不加入擴充功能安裝包。

### 本次更新與驗證

相較上一個 GitHub 發布附件（`schema-contract-17`），本次 `size-binding-29` 主要補強：

- **來源與名稱**：核對所選播放器、貼文卡片與來源身分，避免借用留言 GIF、廣告、外層貼文文字或通用「影片播放器」標籤；動態換片後驗證選片身分，避免沿用失效資料。
- **畫質偏好**：統一使用短邊解析度；自動降級至最高可用畫質時保留原偏好。
- **片段與大檔**：無可靠索引的合適來源可完整下載後裁切，並顯示黃色提醒；起點為已驗證關鍵影格的合適單一 MP4 可省去時間軸正規化中間檔。
- **下載與暫存**：持續收到資料的長傳輸不受整體 20 秒期限中斷；記錄下載、整理、裁切、驗證與儲存耗時，完成／取消／一般失敗後清理，重開工具視窗時回收孤立暫存。移除檔名歷史，重名交由瀏覽器處理。
- **大小顯示**：區分單一檔案與整組 HLS 串流的平均位元率；只有可確認所選影音組合時採用全片估算，避免雙聲道使用六聲道估值，或把音軌重複加總。

上述改進沿用既有 FFmpeg WASM、Mediabunny／WebCodecs、HLS／DASH 解析器與 OPFS，沒有新增執行依賴或擴充功能權限。MP4 索引式下載與 H.264 Smart Cut 是上一版已有的能力，本次進一步改善其適用判斷與暫存讀寫。

本版 Node 測試共 1,019 項：1,017 通過、2 略過、0 失敗。已完成約 2.32 GB 合成有效 MP4 的全片、15 秒片段及取消測試；也以兩部公開短片、7 組畫質／音軌比對大小估值。固定資料測試、既有實站測試與尚未驗證的項目分開記錄，見 [發布回歸與量測摘要](docs/release-regression.md)。

<summary><strong>區間擷取實作限制與未來考慮</strong></summary>

一般直連 MP4 已可利用內部 sample table 定位區間。先確認來源確實回傳 HTTP 206，再只讀索引、所選時間及解碼所需的前後 GOP／音訊；以 256 KiB 區塊共用讀取與有限快取減少請求次數。沒有可靠索引或 Range 被忽略的來源，不宣告局部傳輸能力；若已取得片長且格式支援，可在「片段下載」使用完整下載後裁切補救，並顯示黃色提醒。此補救不設檔案大小上限，實際可處理容量取決於磁碟與瀏覽器；無法確認片長、直播或 DRM 不開放。這項節省的是網路傳輸，與裁切時的編碼加速分開處理。

MP4 是容器格式。切點符合條件時優先直接複製；部分 VP9／WebM 可只重編開頭。H.264／MP4 支援頭尾邊界重編、中段複製：只接受已驗證的 IDR、相容尺寸／profile／色彩與瀏覽器編碼能力，以 avc3 與各接點的 SPS／PPS 保留解碼設定，處理 B-frame 次序及共同音畫時間軸。輸出會實際解碼檢查開頭、兩個接點及尾端；失敗便回退原本的精準轉碼流程。

切點精度仍受原影片影格間隔及音訊封包長度限制。非常短的區間、長 GOP、非相容編碼或邊界佔所選時間超過 60% 時，仍可能重編整個區間，因此 HLS 局部下載不保證處理比下載快。Smart Cut 也不保證所有播放器都支援參數切換；目前驗證包含本機 Chrome 與 FFmpeg 解碼。

本機實測（不含網路下載）：720p／30fps H.264，15 秒片段約 6.48 → 1.82 秒，45 秒約 15.26 → 2.29 秒；公開 HLS 範例的 1080p／60fps、45 秒片段，轉換約 46.46 → 12.58 秒。這是特定素材與電腦的量測，不能推算所有畫質或片長。公開範例同一個 15 秒區間因邊界比例過高，仍使用完整區間轉碼。

探索流程共用媒體欄位規則。開啟視窗先取得播放器摘要，只深入解析目前選中的播放器；單一影片會自動選取，毋須額外操作。背景仍保留有數量／容量限制的播放中繼資料，不保存播放影片內容。Shadow DOM 登記採分批處理；深入掃描具有項目及時間檢查，上限用盡便停止新增探索工作，之後可重新選片／重新整理。這是合作式預算，不能在瀏覽器原生解析函式執行到一半時強制中止。 延後解析佇列只保留媒體資料並去除重複回應，避免一般 API／統計流量擠掉播放資訊；身分、來源及解析器所需屬性分別保留；保留屬性不等於把一般應用資料認定為媒體。選片後優先處理含所選識別的已保留資料，腳本快取命中不消耗解析額度；優先順序不作為來源配對證據。X 廣播亦可在選片時補讀目前文件中的串流 JSON，仍須核對貼文、廣播與播放器識別。
