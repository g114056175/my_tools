# VideoSpeed 0.6.10 驗證

2026-10-27。本輪針對「載入及快捷鍵必須等 popup 才開始」修正啟動流程。測試使用獨立 Chromium／Brave profile；VideoPocket 未修改。

## 已確認的程式缺口

1. 內容腳本只送一次啟動設定要求。背景暫時無法回應時回傳 null，內容腳本不重試，控制程序及快捷鍵可能一直未建立。
2. 背景在選取通知送達前就快取目標，送失敗仍視為已通知。未建立控制程序的頁面又回傳空的成功回覆，可能使後續同影片回報不再取得選取通知。
3. 速度尚未成功套用就標為初始化完成。橋接器短暫不可用時會保留 1×，後續相同影片無法重試。

新版啟動要求有逾時及有限重試，可由聚焦、播放與快捷鍵再次喚醒。選取通知必須取得實際影片 ID 的確認才快取，失敗會有限補送。頁面橋接器亦需確認就緒，缺少時只對目前文件補注入。第一次自動套用暫時失敗會有限補試；成功或使用者手動選速後停止，不反覆鎖速。快捷鍵監聽在 document_start 即註冊，避免等待背景設定後才落在網站監聽器之後。

首次焦點查詢失敗時，啟動要求會重新確認實際聚焦狀態；10 秒緩衝不能替代聚焦確認。未造訪或已離開緩衝的背景新媒體仍不探索，既有背景播放保留控制。

## 截圖中的腳本載入錯誤

`An unknown error occurred when fetching the script.` 對應 Chromium service worker 的腳本載入／註冊失敗。Chrome 官方教學以缺少靜態 import 檔案示範相同錯誤。[官方說明](https://developer.chrome.com/docs/extensions/get-started/tutorial/service-worker-events#optional-debugging-the-service-worker)

0.6.9 的六個本機輸出副本及三種 ZIP 都完整，未發現持續缺檔；因此無法從使用者的 unknown／:0 確定當時哪個檔案或讀取步驟失敗。本輪將背景改為單一 classic 腳本，移除背景的六個模組載入依賴，並加入 manifest 引用與成品完整性檢查。這是減少載入失敗點，不宣稱已重現使用者電腦上的偶發檔案讀取原因。

## 不開 popup 的驗證

可用 `npm run test:autostart` 重跑。本機伺服器提供真正可播放的影片及音訊；只讀取原生速率、影片進度及診斷，不呼叫 popup、getState、refresh 或手動送 activeTarget。

- Chromium：20 次新文件、10 次 SPA 替換影片，皆取得並套用跟隨速度 4×。
- Brave：另外驗證新文件、換片、快捷鍵及下述故障恢復。
- 快捷鍵：實際角括號事件將 4× 改為 3.5×，再回到 4×。
- 同時故意拒絕第一次設定要求、拒絕第一次選取通知並略過首次 MAIN 橋接器載入：候選能自主補回橋接器，首次快捷鍵有效，最後回到 4×；三個故障均有觀測證據。
- 冷啟動：先確認 service worker 已停止，影片新文件載入後確認 worker 重新啟動並套用 4×。不以 target ID 是否改變當作重啟依據，也未附加 worker DevTools。

故障是測試注入，不代表已在實站重現使用者的全部條件。早期測試程式曾有故障頁路由缺失、未保存故障觀測欄位及在攔截之後才監聽按鍵的問題，這些執行不列為有效故障驗收；已修正並重跑。

真實公開 YouTube 另以隔離 profile、不開 popup 驗證：首次載入自動 4×，角括號操作為 4→3.5→4，重載後重新套用 4×；兩次正片進度各增加約 14 秒。未遇到登入、CAPTCHA 或地區阻擋。另一次測試的 Shift+,／Shift+. 實際 DOM key 是逗號／句號，觸發了 YouTube 原生操作；不將該測試造成的 1× 記憶當作跟隨功能失效。

## 回歸與限制

單元與整合檢查包含啟動重試、選取確認、設定讀取恢復、初始化成功判定，以及手動選速取消自動重試。既有 Full／Default、畫質、語系、10 秒活動緩衝、跨 frame 同步與標示穩定性亦重跑。實際結果保存在本機輸出的 VideoSpeed-validation.json。

未全面覆蓋所有網站、廣告與帳號組合；本輪未驗收原生工具列 popup 的瀏覽器外框。先前背景持續新增 Extension context invalidated 的完整條件仍未定位，亦不宣稱本輪已修復；真正凍結的 renderer 尚未完成有效驗證。
