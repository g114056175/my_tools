# 驗證與測試

## 自動測試

在專案目錄執行 `npm ci`、`npm test`。測試涵蓋播放器與來源身分、標題、動態換片、畫質偏好、字幕生命週期、傳輸逾時、暫存清理與區間裁切。

固定 DOM／JSON／Worker／媒體資料用來重現邊界情況；它們不能取代實際網站、登入環境與 CDN 的下載驗收。本機瀏覽器測試亦屬固定資料驗證。

## 實站檢查項目

- 選片：引用貼文、留言 GIF、廣告、多播放器及迷你視窗不混用來源。
- 動態頁面：換片、重新整理與重開工具後，名稱及下載來源仍對應所選影片。
- 畫質：以短邊標示，降級不覆寫偏好，格式與畫質單一選項可正常顯示。
- 下載：全片、音訊、短片段、未知大小、長時間傳輸、儲存及取消。
- 裁切：核對起迄、音畫同步、開頭／接點／結尾可解碼，失敗時安全回退。
- 字幕：重新整理／導覽後舊結果失效，延遲回應不寫回其他影片。
- 清理：完成、取消、一般失敗與異常終止後回收暫存；使用者成品保留。

HTTP 成功、取得畫質清單與下載成品可解碼是不同層次的證據；實站結果應記錄網址、環境及實際完成的步驟，不宣稱整站所有影片均支援。

## 媒體樣本量測

有效 H.264／AAC MP4 樣本約 2.32 GB，1280×720。在 Windows、i5-12600K、約 32 GB RAM 的獨立 Chromium，以忽略 Range、約 17 MB/s 的本機節流來源測試：全片輸出雜湊一致；完整下載後裁切 15 秒可完整解碼；完成與取消後影音暫存均為 0。

15 秒片段處理約 2.43 秒。片段流程每秒採樣的峰值約為 693 MiB Private Bytes、926 MiB Working Set 合計及 2.33 GB 影音暫存。這些是特定合成素材與環境的參考值，未包含 OS 檔案快取與獨立 GPU VRAM，不是容量上限或所有網站的效能保證。

## 大小顯示依據

以兩部公開短片、7 組畫質／音軌組合，先保存清單宣告平均值，再下載並以 stream copy 封裝比較。對應音軌的全片平均值偏差低於 0.15%；多音軌組合不明時可能超過兩倍。將全片平均值套到短區間，也會因場景及分段邊界而有較大偏差。

因此只顯示已知大小或可確認所選影音組合的全片估值；其他情況顯示「大小未知」。上述少量樣本不構成全部網站的誤差保證。

參考：[Apple 串流範例](https://developer.apple.com/streaming/examples/)、[Shaka Angel One](https://storage.googleapis.com/shaka-demo-assets/angel-one-hls/hls.m3u8)、[HLS AVERAGE-BANDWIDTH 定義](https://www.rfc-editor.org/rfc/rfc8216.html#section-4.3.4.2)。
