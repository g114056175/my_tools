# C++ 移植的模型試跑建議

查核日期：2026-09-13。以下是根據專案難度提出的工程分工，不是本專案已完成的模型效能／費用評測；不會自動變更任何模型設定。

## 建議

| 工作 | 建議起點 |
| --- | --- |
| 一個模型負責整體移植 | GPT-5.6 Sol，Medium；音訊／資源疑難再提高推理程度 |
| 想測試更低成本的選擇 | GPT-5.6 Terra，先 Medium，對較多狀態的 UI 任務可 High |
| 文件、字串、既定樣式、重複測試資料 | GPT-5.6 Luna；不要單獨負責整套音訊移植 |
| 難以重現的 COM、race、播放亂序、錄音生命週期問題 | 留給 Astra 或 Sol 做聚焦診斷／審查 |

官方將 Sol 定位於複雜工作、Terra 定位於日常開發、Luna 定位於明確重複任務，並建議從足以達標的較低推理程度開始。[OpenAI 模型與推理程度說明](https://learn.chatgpt.com/docs/models)

上述 Medium/High 是本專案的試跑設定，不代表官方保證此設定能完成 Win32 音訊工具。可用模型及推理選項依帳號／用戶端而異；沒有在此假設固定訂閱價格或節省百分比。

## 如何比較才有意義

1. 先讓 Terra 做下列單一 UI 試作，限於新的 native-prototype/，不得修改現有 WPF 版。
2. 使用相同規格、輸入 WAV、驗收清單；必要時以獨立乾淨分支讓 Sol 完成相同試作。
3. 比較實際通過案例、修正回合、總耗時／實際用量、EXE 大小，以及程式碼能否維護。不要只比較一次回覆的長度或單次成本。
4. Terra 如果能一次或少量修正通過 UI 驗收，就繼續用它做有明確介面的模組；COM/音訊整合仍安排較強模型審查。

## 可直接使用的第一階段任務

> 先讀 README.md、docs/CPP-MIGRATION.md、現有 Controls/ 與 MainWindow 程式碼，使用 docs/preview.png 作為風格参考。只在 native-prototype/ 建立 C++ Win32 UI 試作，保留現有 WPF 版。不要加入 Qt、Electron、WebView、.NET、FFmpeg 或網路服務。
>
> 第一階段只讀合成 WAV：深色版面、來源能力提示、真實 PCM 波形、已播放／未播放示意狀態、裁切框、比例範圍條、5 秒至全長的刻度連續拉伸、全部／30 秒建議、確認對話框。尚未接上的錄音／MP3 功能需明確停用，不能假裝可用。
>
> 提供可重複建置的腳本，使用靜態 CRT，保留系統字型及鍵盤焦點。驗证最小尺寸與 DPI，回報 EXE 大小、依賴、通過及未完成的測試。第一階段驗收完成後停止，不自行宣稱完整移植完成。

完整音訊模組的後續工作請分階段下達，避免把低成本模型的返工量誤當成節省。
